# 批量测试任务流程

2026-10-28，基于v0.8.0及后续UI修正的源码变更；本轮不提交、升级、打包或替换桌面应用。仅批量测试改为任务流程，基础检测保持快捷工具，应用管理与代理设置/单行footer不改流程。

## 使用顺序

1. **任务列表**：默认空态，点击“创建任务”。列表显示名称、模式、固定端点数和最近执行状态。
2. **创建/编辑**：填写名称、模式，选择组合/应用与明确端点，配置参数和授权绑定；点击“保存任务”。保存不解析DNS、不连接目标或代理。
3. **任务详情**：查看固定范围和参数；点击“开始执行”。预检展示本次范围、预算、路径及变化，确认后才发起测试。
4. **过程与报告**：在详情查看排队/运行/停止收尾、逐端点状态和逐次结果。完成后报告自动持久化，不依赖页面是否开着。
5. **再次执行**：使用新执行编号创建新记录；历史选择器可查看任一次报告，不覆盖前一次。编辑任务产生新修订，旧报告仍展示当时范围与参数。

多个组合按端点ID去重；混合协议组合可以先选，再明确取消不适用应用/端点，不静默忽略参考规则或未知协议。默认值与公共/授权边界保持。

## 范围与授权

任务固定服务端从目录解析的端点ID、执行语义及应用/组合来源。组合后来新增成员不自动加入。无关目录修订及名称变化不单独阻止执行；端点地址/端口/协议/ALPN或关联变化、选中项删除要求编辑更新范围。

每次预检核对当前精确Permit和代理路径，token有效30秒，开始时在共享mutation门闩中重查；过期/相关配置变化则重新核对。保存任务不是永久负载授权。目标及代理全部DNS答案/CIDR、控制端口、额度/过期、资源检查和停止回收继续使用既有执行器。

## 持久化与恢复

独立批量任务数据根，任务和执行分开存储：最多100任务/8MiB，报告单份16MiB，总100份/100MiB，容量满明确拒绝新执行，不自动删除旧报告。开始前预留报告预算，accepted先落盘再注册worker，取消窗口有注册守卫，不能留下无法停止的活动占位。

执行开始/变化中最多每秒保存checkpoint；真正结束连接和DNS收尾后自动归档完整报告，成功后才允许内存压缩。归档失败尽力保存完整终态到pending，保留内存结果并阻止新旧批量替代；“重试保存报告”只做磁盘操作、不再发送请求。checkpoint失败不会把快照误记为已持久化，相同内容也会节流重试。

重启恢复未完成记录为interrupted，不恢复连接、不自动续跑；只有初始pending的记录不能声称恢复完整过程。已保存终态但报告写失败的pending可以继续归档；完整报告优先于残留pending，安全清理或纳入实际双份磁盘额度。磁盘损坏/符号链接/超限不静默覆盖。

任务创建有task/create UUID，执行有独立execution UUID。未知保存/执行只核对原编号，不自动重发；再次执行不会复用待核对编号。持久执行幂等检查早于token过期检查，旧底层入口不能复用任务执行ID绕过记录重跑。

## 界面隔离

任务列表、编辑和详情是批量页内部视图，不增加顶级导航。查看历史执行与当前活动执行分开，不能因为选中旧报告误停新执行；切到列表或其他页面仍保留运行/未知状态锁和单个轮询器。报告按冻结路由呈现，不用当前设置覆盖历史。
