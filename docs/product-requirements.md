# AoNet 产品需求：通用办公网络故障诊断

日期：2026-10-27。状态：需求基线；不是已实现功能清单。

## 1. 定位与成功标准

AoNet 是面向多终端办公网络的本地运维诊断工具。典型环境有上百员工、数百手机和电脑、多条普通企业宽带，关键业务为航司、OTA、Galileo、Sabre、Amadeus、IBE+。

核心问题：**当前什么访问异常，故障更可能在哪一段，有什么证据，运维下一步应验证什么？**

工具应放到任意网络即可开始使用，不要求事先提供固定拓扑、路由器品牌、设备管理员账号或全网部署。设备指标和其他位置的对照观测可以增强证据，但不能成为基本诊断的前置条件。

成功不是“显示几项成功/失败”或“达到某个并发数字”，而是缩小排查范围，保留可复现证据，避免将网站限制、账号问题或探测协议限制误报为网络故障。

## 2. 核心流程（目标能力）

1. 选择内置业务预设或填写明确的目标地址及接入方式；首次不选择目标、不自动发送流量。
2. 查看将执行的步骤、目标与流量预算，明确启动。
3. 自动获取可用的本地网络信息，依次检查 DNS、响应路由跳点、TCP、TLS、适用的 HTTP 入口。
4. 按层展示成功、失败、超时、未执行、权限不足和不适用，保留原始结果和时间。
5. 与用户选择的正常对照目标、历史记录或其他可用出口结果比较，形成有依据的疑似原因。
6. 导出“现象—证据—疑似原因—下一步验证”的诊断报告，供内部运维或运营商处理。

默认故障诊断串行且单独限制新建连接速率，避免在连接资源已经紧张时加剧问题。并行连接验证是另一项显式操作，不在普通检查失败后自动升级执行。

## 3. 分层证据与结论边界

| 层次 | 应记录的证据 | 不应直接推断 |
| --- | --- | --- |
| 本机 | 接口、地址、可用路由/网关信息及采集权限 | 单机状态代表几百台终端 |
| DNS | 使用的解析方式、返回地址、耗时、错误 | 不同地址必然被劫持；绕过企业 DNS 就是正确修复 |
| 路径 | 探测方式、TTL、响应地址、RTT、超时、截断原因 | 第一个不响应跳点就是故障点 |
| TCP | 目标实际 IP/端口、建连耗时、成功/拒绝/超时 | 建连成功表示业务正常 |
| TLS | SNI、证书校验、握手结果及错误 | 关闭证书校验后成功表示网络无问题 |
| HTTP | 方法、收到响应与否、状态码、重定向位置 | 403/405 等同网络断开，302 等同业务失败 |
| 业务入口 | 产品、接入方式、依赖、已验证与未验证步骤 | 官网或登录页可达代表查询、预订、出票正常 |

traceroute 是响应跳点发现，不是完整拓扑扫描。NAT、透明设备、ICMP 限速、过滤、回程问题、非对称路径、负载均衡都会影响结果。后续跳点或终点有响应时，中间的星号不能被报告为该路由器丢弃业务流量。最后响应跳点只是观测边界，不是已证明的故障边界。没有响应的节点仍应显示为未知，不“补全”设备。

参照：[RFC 1812](https://www.rfc-editor.org/rfc/rfc1812)、[RFC 5508](https://www.rfc-editor.org/rfc/rfc5508)。这些规范描述机制，不保证实际网络设备严格遵循。

## 4. 重点场景：疑似连接资源或运营商策略限制

用户实际事件：一条主力宽带曾被运营商怀疑 PCDN，并被限制连接数为 1。该事件是诊断场景来源，不是工具能够自动确认的网络事实。

需要区分：
- 同时保持的 TCP 连接数量；
- 新建连接/映射的速率；
- HTTP 请求速率；
- 终端、路由器/NAT、运营商路径、远端服务各自的资源或策略。

普通单次探测可能正常，因此需要独立的低负载受控对照实验：先单连接，再逐级少量并行连接；分别改变占用数量和新建速率；记录释放已有连接后的恢复情况。可获得远端日志时对照远端实际接受连接数，不能只用客户端配置值代表实际连接数。

实验要求：
- 仅自有或明确授权的专用端点；默认低档，有并发、速率、总次数、字节、时长和停止阈值。
- 服务器容量和本机文件描述符等也可能限制结果；失败时不自动加压、无限补连、重试或换目标绕过限制。
- 停止后等待 worker/socket 释放，明确进入终态。
- 本机回环自检只证明工具功能，不经过宽带，不能作为运营商连接容量证据。
- 无受控远端时标记“未验证”，不改用航司、OTA、GDS 生产系统进行承载实验。

报告示例：“本机到受控端点的单连接正常；保持已有连接时，新增连接多次超时；释放后恢复。观察支持疑似状态资源/并行连接限制，但尚不能确定限制位于本机、路由/NAT、运营商或远端。”

不得输出“已确认运营商识别为 PCDN”“全网最大连接数就是 N”或凭单机试验推断全部宽带额度。运营商归因需要独立策略证据。HTTP 429 仅表明响应方报告请求限流，不证明运营商会话上限。

参照：[RFC 6888](https://www.rfc-editor.org/rfc/rfc6888)、[RFC 6585](https://www.rfc-editor.org/rfc/rfc6585)。外部端口配额、会话状态配额和映射创建速率不是同一个数量。

## 5. 业务连接预设

覆盖 Galileo/Travelport、Sabre、Amadeus、IBE+，并与既有航司、OTA 首页书签区别展示。

每项按具体产品和接入方式建档：浏览器工作台、桌面客户端、API、认证与公共依赖不能混用。连接配置详情应包含：
- 名称、供应商、别名、版本/适用范围、生产/测试环境；
- 真实入口或主机、端口、协议、用途；
- 精确主机与防火墙通配规则的区分；
- 文档明确给出、URL 标准推导、未知三类依据；
- 官方来源、资料核对日期、已知发布日期；
- 未公开、待确认或租户专属配置，以及未覆盖的业务步骤。

没有证据的字段留空并解释，不默认填 443，不用品牌官网代替业务服务器。通配域不枚举子域，不生成探测地址。不保存密码、token、PCC、Office ID、GTID 或其他实际账号/凭证。

本批连接预设为**只读参考目录**，打开详情不产生目标流量，不进入现有 HEAD 探测选择器、列表复制/导入导出或承载授权。未来可执行的 TCP/TLS 分层诊断需单独设计低预算准入，不能复用授权连接保持模式绕过权限。

## 6. 分期与验收

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| 本批：需求与连接资料 | 本文、官方资料预设、GUI 配置详情 | 四类供应商可查看；未知值/来源清楚；Cloud 23 规则完整；打开资料零目标流量；既有55目标与授权功能不受影响 |
| 基础诊断 | 本地信息、DNS、响应路由跳点、TCP/TLS/适用 HTTP、证据报告 | 不要求拓扑；模拟 DNS 失败、TCP 拒绝/超时、TLS 失败；路径中间不响应但终点成功不误判；取消后清理完成 |
| 连接异常验证 | 受控远端、低档分级、占用与新建速率分离、恢复对照 | 已知上限1的本地模拟能识别现象；区分 HTTP 限流；未知远端或缺对照时不臆测归因 |
| 持续观测与对照 | 历史基线、故障时间线、可选多位置/多出口结果 | 不把单机结果说成全网；明确样本位置/时间；不要求能自动选择不可控出口 |

后续增量已实现独立单目标DNS、系统路由追踪、TCP及同一连接TLS诊断，具体操作和限制见[分层诊断说明](layered-diagnostics.md)。本批不发送诊断HTTP请求，不包含完整本地接口盘点、并发连接限制验证或自动根因归属；不能将基础分层观测称为整个上表全部完成。每次交付记录实际执行的平台、用例和限制，不将已有文档中的测试数量当作新版本验收。

## 7. 不做的事

不自动修改 DNS、路由、防火墙、系统连接限制或网络设备配置；不自动登录订座系统、查询旅客/订单、预订出票；不绕过网站风控或运营商策略；不扫描未知内网或穷举主机；不把服务暴露为公网多用户控制端；不以高并发请求第三方站点验证办公网络容量。
