# 目录组合批量测试

2026-10-27，新增第三个入口“批量测试”，保留站点维护左右分栏和搜索调整。后按用户要求升级为 v0.7.0，构建 macOS arm64 应用，正常退出旧版并打开新版；本批尚未提交代码。

## 使用

1. 多选组合；同一站点ID在多个组合只保留一个目标，不同ID即使同URL仍保留独立记录。
2. 选择公共低频HTTP、授权HTTP或授权TCP。默认不选组合、不运行。
3. 设置执行并发、连接上限、队列容量、每站次数、起发速率、单次超时和总时限。TCP另设每站连接上限、每连接保持时长。
4. 授权模式在站点预览逐站绑定精确匹配的授权。授权端点弹窗可新增记录；完整预览确认后保存，不发起测试。原授权和代理路径字段保留，demo记录不持久化。
5. 点击开始；授权批次还需核对冻结站点、绑定和总预算后明确确认。结果每站一行，展开查看逐次状态、码、耗时、IP和原因。
6. 停止后不再派发，等待socket/任务回收及不可取消的系统DNS收尾。不自动重跑、不对失败补次数。

## 参数及指标

- 最多1000站、10000次计划；队列1–256，满时暂停生产，不丢任务。待生成并非占用完整worker。按站点轮转选择可运行项，冷却/授权等待不占连接额度。
- 公共HTTP：执行/连接上限1–4，每站1–3次，起发1–2/秒，总时限1–120秒。同域仍至少30秒，共享现有持久冷却；等待可能导致计划未全部执行。
- 授权HTTP/TCP：执行/连接上限1–1000，每站1–100次，起发1–1000/秒，总时限1–300秒。2026-10-28 对齐现有引擎MAX，而非公共检查额度；实际仍受Permit更严格额度/到期及本机可用资源限制，同许可多站共享额度。1000是产品上限，不是性能承诺。
- HTTP单次超时1–30秒，包含解析/建连/响应；固定HEAD/HTTP1独占短连接，无GET fallback、自动重试、重定向、正文读取、系统代理或新代理配置。
- TCP建连超时1–30秒，每站连接上限不超过全局，保持1–30秒。执行并发包括建连和保持，不保证始终满连接；不发应用数据，远端关闭即结束。
- HTTP“连接额度占用”是本机控制额度，不称其为远端真实连接数。TCP另报当前已建立与峰值。HTTP调度使用min(执行并发,连接上限)，解析也占执行名额，较保守。
- TCP耗时为解析＋建连（不含保持）；逐次另报保持毫秒数。HTTP耗时到响应头，不是业务延迟。
- 收到HTTP响应与2xx/3xx、4xx/5xx、网络错误分开；403不等于断网。TCP建连成功不等于保持完整或业务正常。
- `waiting_admission` 是队列的子集，不重复求和；取消/总超时下的未执行数不计网络失败。批次“执行结束”不等于全部成功。

## 数据和权限

- 启动用catalog revision/组合ID/可选站点子集，服务端重新解析并冻结；未保存/已删除/不适用成员整批拒绝，不静默忽略。
- 目录可保存不等于可执行。公共端口/地址规则保持；授权HTTP必须完整规范URL相同、TCP必须规范host+有效port相同，且mode匹配。不是同CIDR任意端点授权。
- 所有DNS答案校验并固定一个地址，禁止控制服务，保留CIDR/特殊地址/公共保护域策略。授权覆盖预算并在执行检查到期。
- 新旧批量共用manager/current/settle，保留旧API。UUID跨入口拒绝，同请求幂等；只有当前保留完整有界明细，历史轻量请求至多1024且总4MiB，不恢复历史、不导出。
- HTTP/IPC同业务逻辑，HTTP保留Host/Origin/token/JSON/1MiB请求限制，不暴露任意路径或shell。
- 三页按来源聚合活动锁，批量与基础工具/目录写入互斥。其他窗口运行只读查看，不自动接管停止所有权。
- 启动结果未知时查询原UUID，不重发；`accepted:false`仅表示查询瞬间无记录，不能排除原请求仍等门闩，因此保留不确定锁。若请求永久没有到达，只能在确认没有后台任务后重启应用会话恢复，不提供一键放弃并重发。

## 2026-10-28：资源误拦截修复（源码，未重新打包）

原FD预算固定预留256，导致软限制256下2条连接也需258。改为实际已开FD + 本轮新增连接需求（本机demo双倍）+ 动态安全余量：软限制的1/16，最少8最多64。macOS通过本进程proc_pidinfo采样，有界缓冲和增长重试；Linux读取/proc/self/fd，其它Unix尝试/dev/fd。采样失败明确报错，不跳过检查，不提升系统限制。预算只是启动时快照，运行时仍可能因资源变化失败，并如实展示。

模式名称明确区分“公共连通性检查 / 授权负载 · HTTP / 授权负载 · TCP”；公共限制不变，授权并发/连接/起发上限从32对齐1000，仍严格执行精确目标授权与资源限制。默认值不提高；前端消费后台mode limits。队列容量、总尝试次数、时长和明细内存边界保持。

在隔离子进程软限制256下验证实际FD采样及2连接预算，不更改用户系统或父会话限制。189项Rust、93项前端/版本测试通过，Clippy、fmt、Tauri locked/offline check及diff检查通过。本机受控HTTP实际请求通过，未对公共目标运行负载。此修复尚未包含在已打开的v0.7.0包内。

## 验收与限制

已在隔离数据根、统一启动入口中使用本会话自建的本机HTTP/TCP fixture进行浏览器验证：
- 新增站点和两个组合，跨组同ID合并为1站。
- 授权完整预览、保存、逐站绑定和开始前预算确认。
- HTTP每站3次、队列1：三次HEAD 200，显示每次耗时/IP，完成后连接额度0。
- TCP两次各保持约1002ms，显示解析＋建连约0.2–0.4ms，连接归零；长保持中停止，剩余标未执行，维护与基础开始保持互斥。
- 375px视口宽度与scrollWidth同为375，双参数列，分组/主内容纵排；恢复桌面。无console错误与失败请求。

公共预设仅作选择/预览，未向公共站点发起批量测试。本机服务不代表真实外网能力。原生IPC完成编译检查，不等于已完整人工操作桌面版；Windows未原生验证。DNS draining已加入仅测试用的真实阻塞resolver线程注入：普通停止等待真实返回，应用退出走有界grace并保留真实pending，不宣称系统DNS已取消；新TLS worker验证不受信任CA拒绝，没有新增可信fixtureCA成功矩阵。

最终联合验证：185 项 Rust 测试、92 项 JavaScript/版本测试通过；Clippy 全 targets -D warnings、两个manifest fmt、Tauri locked/offline编译检查及git diff --check通过。开发中曾出现HTTP fixture服务端EOF统计滞后导致峰值断言失败（179通过/1失败）；改为服务端明确关闭并统计请求处理区间，另独立断言客户端连接额度峰值后复测通过，未放松生产连接上限。

独立复核发现并修复的边界均有回归：满队列两站轮转公平性、应用退出DNS有界收尾、被拒绝的新请求不清旧结果、总时限不误计用户取消、DNS内层超时归入timed_out。前端状态协议严格校验external_busy来源，并聚合基础工具/旧任务/批量/目录写入和结果不确定锁。
